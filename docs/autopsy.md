# Decision Autopsy (USP 1) — Methodology & Specification

> **"Turn every failed move into an empirical investigation."**

## 1. Overview & Motivation

In hosted autonomous game challenges, AI agents often fail silently or produce baffling mistakes. Traditional bot logs only record final scores or raw console output, leaving developers and competition judges guessing why a model failed.

**Decision Autopsy** bridges the gap between model intention and real-world execution. By comparing the model's predicted probability distribution against the actual game environment feedback for every single step, Decision Autopsy automatically diagnoses failures, isolates root causes, and generates testable hypotheses for prompt optimization.

---

## 2. Verdict Taxonomy

Every recorded step is evaluated against transparent, deterministic decision rules and assigned one of six standardized verdicts:

| Verdict | Severity | Primary Condition | Interpretation |
| :--- | :---: | :--- | :--- |
| **`illegal_move`** | `0.95` | `retries > 0` or `legal=False` or rejected action | The model attempted an action excluded or forbidden by the game rules. |
| **`game_over`** | `1.00` | `done=True` and `good=False` | The chosen move directly concluded the game in defeat (e.g. fatal collision). |
| **`confident_miss`** | `0.85` | `probability >= 0.70` and `good=False` | Model exhibited strong conviction (≥70%), yet the game outcome was negative. |
| **`uncertain_miss`** | `0.60` | `probability < 0.70` and `good=False` | Model recognized high uncertainty (<70%), and the action failed. |
| **`lucky_hit`** | `0.40` | `probability < 0.50` and `good=True` | Model had low confidence (<50%), but the move unexpectedly succeeded. |
| **`as_predicted`** | `0.05` | `probability >= 0.50` and `good=True` | Model made a confident or standard move and the game environment confirmed success. |

---

## 3. Core Rules & Severity Weighting

1. **Priority Ordering**:
   - `illegal_move` takes precedence over outcome classification because the game engine refused the action before normal state transition.
   - `game_over` takes priority over non-terminal misses to highlight catastrophic failures.
   - `confident_miss` is weighted higher than `uncertain_miss` because miscalibrated overconfidence is more dangerous than recognized uncertainty.
   - `lucky_hit` flags instances where the bot succeeded despite low confidence, alerting engineers to stochastic drift.

2. **Severity Scale**:
   - Severity is a normalized floating-point value from `0.0` (benign / expected) to `1.0` (fatal game over).
   - Worst-case queries (`bot.autopsy.worst(k=5)`) prioritize high-severity items to quickly isolate regressions.

---

## 4. Transparent Hypothesis Framing

A fundamental non-negotiable principle of Beat the Bot is:
> *Never invent strategic explanations or present causal inferences as absolute facts.*

All explanatory notes generated by Decision Autopsy follow a strict, transparent template:
1. **Model Intention**: State the chosen action and the exact probability assigned by Laya.
2. **Environment Response**: State the exact feedback returned by the game server (`good`, score delta, error message).
3. **Testable Hypothesis**: Explicitly frame the deduction as a hypothesis for question engineering.

### Example Hypotheses Generated by Rules:
- **Confident Miss Note**:
  > *"Laya was 86% confident in choosing 'move_right', but the game reported an obstacle collision. Hypothesis: the 'Which lane is safe?' question formulation failed to account for obstacles 2 steps ahead at high velocity."*
- **Illegal Move Note**:
  > *"Laya selected 'jump', which the game validator rejected (1 retry). Hypothesis: the legal action space was restricted by wall proximity without updating the candidate options prompt."*
- **Lucky Hit Note**:
  > *"Laya had only 32% confidence in 'stay', yet the move succeeded (+10 points). Hypothesis: successful survival was driven by random obstacle clearing rather than deliberate strategic certainty."*

## 5. Inspection & Verification Interfaces

### 1. Terminal CLI
Run offline autopsy reports directly on any recorded session log:
```bash
# Print readable terminal report with worst cases
python -m bot.autopsy logs/runs/20261012-101500-ab12.jsonl

# Output JSON structure to stdout or file
python -m bot.autopsy logs/runs/20261012-101500-ab12.jsonl --json -o autopsy.json
```

### 2. HTTP REST API
Query autopsy results dynamically via the backend server:
```http
GET /api/runs/{session_id}/autopsy HTTP/1.1
```

Response matches `contracts/autopsy_item.schema.json`:
```json
{
  "session_id": "20261012-101500-ab12",
  "summary": {
    "total_steps": 25,
    "as_predicted": 22,
    "confident_miss": 1,
    "uncertain_miss": 1,
    "lucky_hit": 0,
    "illegal_move": 0,
    "game_over": 1
  },
  "items": [
    {
      "step": 24,
      "verdict": "confident_miss",
      "expected": "Expected safe outcome for action 'move_right' (88% confidence)",
      "actual": "Game returned: Collision with obstacle",
      "note": "Laya was 88% confident in 'move_right', but game outcome was negative. Hypothesis: question formulation exhibited high confidence despite ambiguous or misread state features.",
      "severity": 0.85,
      "question_id": "perception_direct_v1",
      "probabilities": { "move_left": 0.05, "stay": 0.07, "move_right": 0.88 }
    }
  ]
}
```
